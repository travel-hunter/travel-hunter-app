## 6. 이번 회의에서 결정이 필요한 항목

| 결정 항목 | 결정이 필요한 이유 |
|---|---|
| 스테이징 도메인 | 외부에서 접속 가능한 테스트 주소가 있어야 운영 검증을 시작할 수 있음 |
| Cloudflare 담당자 | Tunnel 생성과 도메인 연결 권한이 필요함 |
| SMTP 담당자 | 비밀번호 재설정 이메일 발송 계정과 발신 도메인 확인이 필요함 |
| Kakao/Google OAuth 담당자 | 외부 서비스 관리자 화면에서 로그인 복귀 주소와 비공개 키 설정이 필요함 |
| SOLAPI 담당자 | 알림톡 채널, 승인 템플릿, 발송 비용 기준 확인이 필요함 |
| 스테이징 검증 일정 | 개발 완료 후 실제 환경 검증 완료 시점을 확정해야 함 |
| Jenkins 진행 시점 | 수동 검증 후 자동화할지, 검증과 병행할지 결정 필요 |

## 7. 주요 리스크와 대응 방향

| 리스크 | 영향 | 대응 방향 |
|---|---|---|
| 실제 환경값 미준비 | 스테이징 검증 시작 지연 | 도메인, 계정, 서버 접근 권한을 먼저 확정 |
| 외부 서비스 설정 불일치 | 소셜 로그인, 이메일, 알림톡 검증 실패 | 로그인 복귀 주소, 발신 도메인, 결과 수신 주소를 스테이징 도메인 기준으로 통일 |
| 유료 발송 비용 발생 | SOLAPI/SMS 검증 비용 발생 가능 | 실제 발송 전 승인 기준과 테스트 대상 수를 제한 |
| 자동 배포 미구현 | 당분간 수동 배포 필요 | 첫 운영 검증은 수동으로 진행하고 Jenkins는 후속 자동화로 분리 |
| 외부 도메인 접속 실패 | 이후 모든 provider 검증 지연 | `/api/health`와 핵심 화면 접속을 가장 먼저 확인 |

## 8. 다음 실행 순서

1. 스테이징 도메인과 Cloudflare Tunnel 담당자를 확정한다.
2. 서버에 실제 환경 파일을 준비한다. 실제 secret 값은 문서나 채팅에 공유하지 않는다.
3. 스테이징 서버를 기동하고 `/api/health`를 확인한다.
4. 로그인, 정책, 일정, 마이페이지 화면을 실제 도메인에서 확인한다.
5. SMTP, Kakao/Google OAuth, SOLAPI 순서로 외부 연동을 검증한다.
6. 검증 결과와 실패 항목을 작업지시서 기준으로 기록한다.
7. 운영 검증이 안정화되면 Jenkins 자동 배포와 후속 기능 개발 우선순위를 확정한다.

## 9. 보고 결론

개발 관점에서는 MVP 핵심 기능과 검증이 완료된 상태다. 현재 병목은 코드 개발이 아니라 실제 스테이징 환경 준비와 외부 서비스 계정 연결이다. 이번 회의에서는 도메인, 계정 권한, 담당자, 검증 일정을 확정하는 것이 가장 중요하다.
